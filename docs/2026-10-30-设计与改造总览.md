## 二、设计探索历程（为什么最后是手账风）

用户一开始不知道想要什么，经历了 6 轮方向调整。**这段过程本身就是重要记忆**——
下次不要再从「暖色调 + 宋体 + 卡片」这个假设出发。

| 版本 | 方向 | 结果 |
|---|---|---|
| v1 | Claude 设计系统（排版微调） | ❌ 看不出区别（600 字重在中文里不生效） |
| v2 | 加大差异（宋体 34px） | ⚠️ 有差异但不够 |
| v3 | 大胆版（深墨黑 + 40px 宋体） | ⚠️ 太硬 |
| v4 | 温柔文青（灰调青绿 + 柔和深青） | ⚠️ 对但不够大胆 |
| v5 | 编辑式列表（舍弃卡片网格） | ⚠️ 方向好但太素 |
| **v6** | **V3 结构 × V4 质感** | ✅ 用户认可结构 |
| 大厂四风 | Apple / Linear / Stripe / Nike | 用来「找感觉」 |
| **四种纸** | 横线本 / 方格手帐 / 纸质书 / 牛皮纸 | ✅ **用户选方格手帐** |
| **手账风** | 方格纸 + 图钉 + 胶带 + 贴纸 + 随机倾斜 | ✅ **最终方案** |

### 关键教训

1. **不要只改参数，要换参照物**——前 6 版都在同一假设下打转，用户只会说「不对」。
   给 4 个风格完全相反的方案（大厂四风），用户立刻能指认。
2. **中文没有 600 字重**——`Microsoft JhengHei` 只有 Regular/Bold，600 会被就近匹配到 700，
   所以「字重 700→600」完全无效。改字重必须用 400 或 700。
3. **系统其实装了 Noto Serif TC**——之前误判「没装会 fallback 到 SimSun」，
   用 canvas measureText 检测字体是不可靠的，要查注册表。

## 三、已落地的改动（正式代码）

### 1. 移动端顶栏收敛

**问题**：390×844 下顶栏占约 400px（5 行），内容要滑半屏。

**改法**（`@media (max-width:860px)`）：
- `.hwrap` 改 `flex-wrap:nowrap` → 品牌 + 搜索 + 齿轮一行
- `.brand .verbadge` 隐藏（窄屏省宽度）
- `.subbar` 改单行横向滚动
- `nav#nav` → `position:fixed` 底部 Tab Bar（7 项 grid）
- `main`/`footer` 加 padding-bottom 让出高度
- 既有浮层（`.pickbar` / `#pwaupd` / `#pwahint` / `.memwarn`）上移避让

**踩坑**：`header{backdrop-filter:blur(8px)}` 会创建包含块，让子元素 `position:fixed`
相对 header 而非视口定位（nav 卡在 y=42）。移动端必须关掉 backdrop-filter。

**结果**：header 400px → **96px**，nav 落到 y=791（视口底部），桌面端 103px 未变。

### 2. 全局统一 `--ease-ios`

**问题**：39 个 transition 里 26 个用了 `--ease-ios`，14 个显式 `ease`，**23 个隐性默认 ease**
（简写里没写缓动 = 用了浏览器默认）。

**改法**：
```css
*,*::before,*::after{transition-timing-function:var(--ease-ios)!important}
```
**必须 `!important`**：`*` 优先级 (0,0,0) 压不过类选择器里的 transition 简写。

**不破坏降级**：`data-anim="off"` 靠 `transition-duration:0s!important` 归零，与 timing-function 无关。

**结果**：5 个代表元素 computed timingFunction 全为 `cubic-bezier(0.32,0.72,0,1)`。

### 3. 卡片数据去重

**问题**：每张卡片同一份数据出现两次——
`pmeta` 有「38 知識點 · 49 題」，`foot` 又有「38 知識點」「📝 49 題」，**12 张全部如此**。

**改法**：`pmeta` 只留「掌握度 X%」；`foot` 统一为 `📖 章 / 🎯 知識點 / 📝 題` 三个 pill；
`.foot` 改 `flex-start` + `gap`。顺手删掉单元卡冗余的「進入 →」。

**WCAG 实测**：浅色 标题 14.36 / 简介 7.66 / 次要 4.59 / pill 5.47；深色 6.09–13.23 → 全部 ≥4.5。

### 4. 分页切换转场（View Transitions API）

**改法**：
```js
window.addEventListener('hashchange', function(){
  var off = document.documentElement.getAttribute('data-anim')==='off'
         || matchMedia('(prefers-reduced-motion:reduce)').matches;
  if (document.startViewTransition && !off) {
    try { document.startViewTransition(function(){route();}); return; } catch(e){}
  }
  route();
});
```

```css
::view-transition-old(root){animation:vt-out .32s var(--ease-ios) both}
::view-transition-new(root){animation:vt-in  .32s var(--ease-ios) both}
::view-transition-group(root){animation-duration:.32s;animation-timing-function:var(--ease-ios)}
header{view-transition-name:appheader}
nav#nav{view-transition-name:apptabbar}
::view-transition-old(appheader),::view-transition-new(appheader),
::view-transition-old(apptabbar),::view-transition-new(apptabbar){animation:none}
```

**三个坑**：
1. `::view-transition-group(root)` 默认 250ms，不拉齐到 320ms 会截断进出场
2. 导航栏跟着淡入淡出会叠成两层重影 → 给独立 `view-transition-name` 让它不动
3. 位移只有 12px 时新旧页几乎重叠 → 加大到 26px + `scale(.955)`

**易误判**：`getAnimations()` 的 `effect.getTiming().easing` 显示 `linear` 是**规范行为**
（timing-function 在 keyframe 层），要用 `getComputedStyle(el,'::view-transition-old(root)')` 才读到真值。

### 5. 龙藏体（Long Cang）字体

**来源**：Google Fonts，OFL 免费商用。

**子集化**：原版 **4.91MB → 316KB**（woff2，只保留 1266 个标题用字，压缩 93.6%）。

**实测限制**（重要）：
| 字号 | 效果 |
|---|---|
| 48px 大标题 | ✅ 文艺感强 |
| 34px 卡片标题 | ⚠️ 勉强，笔画变细 |
| 15px 正文 | ⚠️ 偏潦草 |
| **14px 正文** | ❌ 明显发虚 |
| 12px 小字 | ❌ 糊成一团 |
| 数字 | ❌ 笔画太细没分量 |

→ **只给 `.hero h1`（32px）和 `.thead h2`（30px）用**，正文与数字保持系统字体。

**踩坑**：手写体的 ascent/descent 比常规字体大，`line-height:1.3` 会让标题溢出并与副标题重叠，
必须给 1.55 + 下边距。

**维护**：新增标题文字后要重新子集化，否则新字显示不出来。
```python
from fontTools import subset
subset.main(['scratch/_fonts/LongCang-Regular.ttf',
  '--text-file=scratch/_charset_title.txt','--flavor=woff2',
  '--output-file=site/fonts/LongCang-Title.woff2'])
```

### 8. 卡片随机倾斜

```css
.tcard{transform:rotate(var(--tilt,0deg))}
.tcard:hover{transform:translateY(-3px) rotate(var(--tilt,0deg))}
```
```js
function tiltCards(){
  document.querySelectorAll('#app .grid .tcard').forEach(function(c){
    c.style.setProperty('--tilt',(Math.random()*3.2-1.6).toFixed(2)+'deg');
  });
}
```
用 CSS 变量注入，**hover 的位移不会覆盖倾斜**。每次渲染重新随机。

## 七、LQ（卷二）OCR 工作

### 结论：PP-OCR 不可用，PaddleOCR-VL 可用

| | PP-OCR v4 | PP-OCR v6 | **PaddleOCR-VL** |
|---|---|---|---|
| 2019 p4 的 `2(a)` 题干三行 | ❌ 全漏 | ❌ 全漏 | ✅ 完整 |
| 表格 | ❌ 没识别 | ❌ 没识别 | ✅ `<table>` HTML |
| 全页块数 | 44（碎片） | 45 | **11（完整语义单元）** |
| 解析出的题数 | 3 道（**错**） | 3 道（**错**） | **1 道（对）** |

**成本**：CPU 上约 2.5 分钟/页（0.9B 自回归生成），全量 140 页约 5.8 小时。

**工具**：
- `scripts/pastpaper/lq_vl.py` — VLM 识别（可中断续跑）
- `scripts/pastpaper/lq_vl_parse.py` — 解析（不用 x 坐标，直接正则定号）
- `scripts/pastpaper/lq_review.py` — 人工核对页（14 年份已生成）

**进度**：2019 ✅ / 2021 ✅ / 2020 ✅ / 2018、2013、PP 跑中

### 两个已证实的数据问题

1. **`lq_parse.py` 会把小题当大题**——2019 p4 纸上只有 1 道 `2(a)`，parse 切出 3 道。
   所谓「39 道待补号」实为 **39 个错误分组**。
2. **OCR 会成片漏检**——同一页 `2(a)` 题干首行，两版 PP-OCR 都没识别。
