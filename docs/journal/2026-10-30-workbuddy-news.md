# 科研時事 + 三科每日小知識（2026-10-30）

## 关于「时事内容」的立场

用户要「每日科研时事资讯」。这类内容和我平时写的科普不一样 —— 科普是常识，写错了顶多不准确；**时事写错了就是假新闻**。

所以第一步不是写代码，是查证。

### 查证过程

搜索「2026 诺贝尔奖」，拿到 NobelPrize.org 官方页面 + 中国科学报 + 中国新闻网的报道，三方交叉一致：

| 奖项 | 日期 | 得主 | 成果 |
|---|---|---|---|
| 生理学或医学 | 10/5 | Karl Deisseroth、Peter Hegemann、Georg Nagel | 光门控离子通道与光遗传学 |
| 物理学 | 10/6 | Francis Halzen | 冰立方微中子天文台、高能微中子 |
| 化学 | 10/7 | Henri B. Kagan、曾我宪三（Kenso Soai） | 不对称有机合成的非线性效应与自催化 |

正好一科一条，和三科结构天然契合。

**每一条都留了 `url` 指向原始来源**，写进数据文件里，前端渲染成可点的链接。这样用户能自己核对，也避免我成为唯一的信任源。

数据文件的 `_note` 里明确写了规矩：

> 内容必须来自可靠来源并附链接——时事不是常识，宁可少写也不要编。

## 实现

### 数据结构

站点级（跨科目），放在 `data/_news.json`：

```json
{
  "items": [
    { "date": "2026-10-07", "cat": "chem", "t": "标题", "x": "摘要", "src": "NobelPrize.org", "url": "https://..." }
  ]
}
```

`cat` 只影响标签配色（bio 绿 / chem 橙 / phys 青）。

### 渲染

三科总览页底部，做成「剪报」的感觉：虚线上分隔、小纸片、科目色标签、来源链接。

```js
NEWS.slice(0,6).map(nw => `...`)
```

外链一律 `target="_blank" rel="noopener"`。

## 踩的两个坑

### ① 插错了作用域，只有一科显示

每日小知识区块我插在锚点 `${/* DSE 真題分兩張卡… */}` 前面。看起来没问题，**但那个锚点整个位于 `${SUB&&SUB.id==='bio' ? \`…\` : ''}` 之内** —— 那是包 DSE 双卡的条件，只有生物有 DSE 题。

结果：三个科目都跑了 build、数据都注入了（日志明确写着 chem/phys/bio 各 3 条），但**只有生物页渲染出区块**。

我一开始以为是数据没传到前端，去查 `SUB._daily` —— 有，3 条。再查 `document.querySelector('.hn-daily')` —— null。这才回头读模板上下文，发现条件包裹。

**教训：往模板字符串里插 HTML，插完要看一眼外层有没有条件块。** 这种 bug 不会报错、build 也不警告，只有逐页目视才发现。

修法：把每日小知识整块移出条件，条件只保留给 DSE 双卡。

### ② commit message 里的 `${}` 被 shell 吃掉

提交时写了：

```
...被误包在 ${SUB.id==='bio'} 条件里...
```

bash 把 `${SUB.id==='bio'}` 当变量替换，报 `bad substitution`，消息里留下一个空白：`被误包在  条件里`。

**含 `${}` 的文本必须用单引号 heredoc（`<<'EOF'`）或转义。** 这次消息还能读，但信息已经缺了一块。

## 顺带修的一处过时文案

三科总览底部原来写着：

> 🧪 化學區目前 653 個知識點，已整理完成；物理與生物兩區先把結構搭好了，內容可以之後慢慢補進去

这是化学独占内容时期的说法。现在三科都有内容（化学 653、物理 449、生物 485），这段话既过时又误导。

改成：

> 📚 四個分區彼此獨立：筆記、進度、錯題本、複習排程都分開存放，切科目不會互相干擾。

## 数据维护说明

两套内容都是**纯数据驱动**，以后加内容不用改代码：

- `data/<科目>/_daily.json` —— 每日小知识，按「今天第几天 % 条数」轮换
- `data/_news.json` —— 科研时事，手动维护，最新放最前

如果以后想让时事自动更新，可以复用现有的 `daily-audit` workflow 思路，加一个定时任务去抓 RSS 并生成 `_news.json` —— 但时事有真实性风险，**建议保留人工确认环节**，不要让 AI 自动发布。
