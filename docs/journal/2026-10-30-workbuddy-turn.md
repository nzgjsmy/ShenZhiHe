# 2026-10-30 · 分页转场改「翻书页」

> 用户四轮反馈推动的改造。最终方案：翻书的形状 + 只碰合成属性。
> 相关提交：`a5b6684`

## 一、用户的四次反馈

1. 「换分页的时候顶部的栏位和书签的动画会很奇怪」
2. 「我想把动画换成'翻书页'」
3. 「翻页怪怪的，没有那种丝滑和拟真的感觉」→「可能有点立体感会更好」
4. 「没那么丝滑了，可以参考一下苹果官网的设计」

前两次我理解成「改形状」，后两次才发现真正的瓶颈是**性能**和**物理正确性**。

## 二、旧实现的问题（三个）

原来的转场是「旧页淡出上移 + 新页淡入升起」（`translateY(26px)` + `scale(.955)`）：

| 问题 | 说明 |
|---|---|
| 双重动画 | `.view` 自己有 `fade`（opacity 0→1 + translateY 6px），而 `route()` 是在 `startViewTransition` 回调里同步执行的 —— 浏览器快照时 `.view` 的动画才到第 0 帧，**新页快照本身就是半透明的**，再叠一层 `vt-in`，变成两次淡入、中间一度发虚 |
| group 动画没关 | 只给 header/nav 关了 old/new，但真正做「位置/尺寸插值」的是 `::view-transition-group`。栏位高度一变就被插值平移，看起来像文字在抖 |
| 挖出来单独处理 | header/nav 有独立 `view-transition-name`，于是「纸在翻、页头不动」，露馅 |

## 三、翻书页怎么做的

### 轴 = 纸张左缘，不是视口左缘

```css
--vt-hinge: max(0px, calc((100vw - 1180px) / 2));
transform-origin: var(--vt-hinge) center;
```

`.sheet` 是 `max-width:1180` 居中，1440 屏上左缘在 130px。若用 `left`（0px），纸张会绕屏幕外一点转，看着「轴偏了」。

### 翻页的物理：掀开，不是交叉淡化

- 旧页 `z-index:2` 在上层，绕书脊向后掀
- 新页 `z-index:1` 在下层，**静止不动**
- 掀到哪，露出哪

这跟「两个图层交叉淡化」是不同的东西。前者像翻书，后者像换图。

### 全程不透明

第一版让 old 一路 `opacity 1 → 0`，结果是**半透明的旧页叠在新页上 = 重影**，看起来像两个页面并排。

真书的纸不透光，只有翻过 90° 才让开。所以改成：不淡出、靠旋转本身收窄，尾段转到 90° 时投影宽度为 0，自然消失。

## 四、两个真 bug（不是"不好看"，是写错了）

### bug 1：`perspective` 挂错了层，3D 完全没生效

第一版：

```css
::view-transition{ perspective: 900px; }
```

**完全无效。** CSS 的 `perspective` 只作用于**直接子元素**，而 old/new 是它的孙辈（中间隔着 group 与 image-pair）。

更麻烦的是 UA 样式给 `::view-transition-image-pair` 设了 `isolation: isolate`，它会把 `transform-style: preserve-3d` **强制降级成 flat** —— 所以就算逐层加 `preserve-3d` 也传不下去。

后果：
- `rotateY` 退化成「水平压缩」
- `translateZ` 完全失效

**这就是"没有立体感"的真正原因。** 当时看着像图层的宽度在变，一点都不像纸。

修法：挂到 old/new 的直接父级 —— image-pair 上。

```css
::view-transition-image-pair(root){
  perspective: 980px;
  perspective-origin: 34% 47%;
}
```

透视原点也往书脊方向挪（50% → 34%）：原点在正中央时，整张纸以画面中心为消失点变形，左缘反而被拉大翘出视口。

### bug 2：贝塞尔曲线写错了，曲线"回头"

第一版：`cubic-bezier(.3, .5, .2, 1)`

第二个控制点的 x（0.2）**比第一个（0.3）还小**，曲线在水平方向回头。

实测后果：
- 15% 进度就走完了 63% 的角度
- 后 40% 几乎不动

观感就是「卡一下 → 猛地翻过去 → 磨蹭」。

**教训：`cubic-bezier` 的 P1.x 必须小于 P2.x，否则曲线不是单调的。**

后来换 iOS 的 `cubic-bezier(.32, .72, 0, 1)`：起步果断、长尾缓收。

## 五、丝滑的关键：只碰 transform / opacity

第三版为了"拟真"加了：

```css
filter: brightness(.9);              /* 纸立起来背光 */
box-shadow: inset -1.5px 0 0 ...;    /* 纸的切口高光 */
```

结果用户说「没那么丝滑了」。

原因：这两个属性都要在**合成之后重新处理整张 1440×900 的位图**，每帧多一次全画面重算。观感就是"黏"。

苹果的转场之所以顺，正是因为它几乎只用 `transform` / `opacity`，剩下全交给 GPU 合成。

改法：
- 纸边高光 → `border-right`（静态绘制一次，之后跟着合成层走）
- 明暗 → 去掉，立体感全靠透视梯形
- 轻微 `opacity` → 纯合成属性，几乎零成本

```css
@keyframes pageTurn{
  0%  {transform:rotateY(0deg);            opacity:1}
  70% {                                    opacity:.96}
  100%{transform:rotateY(var(--vt-angle)); opacity:0}
}
```

## 六、切页卡顿的真凶根本不是动画

改完之后用户还是觉得不够顺。我装了帧记录器量了一下：

| 切到哪 | 最长帧 |
|---|---|
| 设定页 | **7ms** |
| 真题页 | **305ms** |

差异 43 倍。查下去：

```
真题页：79 道题 · 7381 个节点 · 页面高 29803px
视口：  900px
```

**97% 的内容根本看不见，却在建页时全部完成了布局与绘制。** 而且这 305ms 卡完，View Transition 的动画才开始 —— 观感就是「点了没反应，然后啪一下翻完」。

### 解法：content-visibility

```css
.ppq{
  content-visibility: auto;
  contain-intrinsic-size: auto 317px;
}
```

**挂在单题卡上，不是外层分组。** 试过分组，高度在 334–1533px 之间波动太大，按一个固定值占位会让总高偏差 20% 以上、滚动条明显跳。单题卡实测 229–812px、平均 317px，粒度细得多，总高偏差降到 +7%。

`auto` 关键字会记住该卡渲染过的真实高度，滚过一次就准了。

效果：

| | 改前 | 改后 |
|---|---|---|
| 最长帧 | 305ms | **14ms** |
| >20ms 的帧 | 1–3 个 | **0 个** |
| 页面总高 | 29803px | 31862px（+7%） |

另加 `@media print` 放开，否则列印时未渲染的题目会消失。

## 七、验证方式：精确 seek，不靠等时钟

抓中间帧一开始很难：`go()` 之后到动画真正开始有延迟（浏览器要拍快照），按固定时间点截图，采到的时间轴是偏的 —— 我一度以为"曲线没生效"，其实是截图早了。

可靠做法是**直接拨动画的时间轴**：

```js
const a = document.getAnimations().find(x => x.animationName === 'pageTurn');
a.pause();
a.currentTime = a.effect.getTiming().duration * 0.28;
```

然后截图，这样每一帧的进度都是精确的。

用这个办法才测出"15% 走完 63% 角度"的曲线 bug。

## 八、最终参数

| 项 | 值 | 理由 |
|---|---|---|
| 角度 | `90deg` | 转满 90° 时投影宽度为 0，自然消失，不需淡出 |
| 时长 | `.46s` | 翻一页的合理时长；再长显拖，再短看不清 |
| 缓动 | `cubic-bezier(.32,.72,0,1)` | iOS 的页面推入曲线 |
| 透视 | `980px` @ `34% 47%` | 挂在 image-pair；原点偏向书脊 |
| 移动端 | `78deg` / `.44s` | 窄屏角度收小，否则变形过猛 |

`data-anim="simple"` 时角度归零，退化成纯淡出；`data-anim="off"` 由 JS 直接跳过 View Transition。

## 九、没做到的部分

CSS 3D 做不出真实纸张的**弯曲**和**动态投影**。iBooks 那种 curl 效果是 WebGL 逐顶点变形，CSS 单平面做不到。

现在能给的：梯形透视 + 明暗（已删，为性能）+ 书脊轴 + 不透明掀页。

如果还要更拟真，唯一的路是换 canvas/WebGL，代价是拿不到 View Transition 的快照，得自己截图（`html2canvas` 之类），性能和保真度都会退。
