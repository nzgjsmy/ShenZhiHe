## 起因

用户截图反馈 **PP 練習卷 Q23（進化·演化樹）** 选项区只有四个空白字母框，没有演化树。
题目本身是「按氨基酸差异数建树」的经典题，四个选项 A–D 全是树形图。

## 排查

1. 定位题目：`data/bio/_pastpaper.json` → `years.PP` → `qnum 23`（`pp_PP_q23`）。
   `options` 的 `v` 全是空字符串，靠 `optImg = img/pp/PP/o23.webp` 出图。

   OCR 定位「建構演化樹時」在 y≈620、「演化樹？」在 y≈957，四棵树在 y 1000–1460。

## 修法

```bash
python scripts/pastpaper/pp_recut.py --one PP 9 1000 1480 site/img/pp/PP/o23.webp
# → 1000×519，crop x388..1222 y1022..1455（tight 自动收到墨迹包络）
```

`pp_recut.py` 的 `tight()` 会按 `INK=178` 找墨迹行列并加 14px padding，
所以只要给一个「包含目标、不包含邻居」的粗略 y 范围就够。

# 第二批（2026-11-15）· V0.25.23.21

用户反馈 **2020 Q33** 的图表没有 X 轴标题「高度 (cm)」。

## 根因

`f33.webp` 的下边界刚好卡在刻度数字（10／30／50…）下面，轴标题整行被切掉。
原卷第 10 页 OCR：「高度 (cm)」在 y 1393–1426，Q33 题干在 y 1465 —— 说明裁切只到 ~1390。

## 修法

```bash
python scripts/pastpaper/pp_recut.py --one 2020 10 978 1445 site/img/pp/2020/f33.webp
# → 1000×703，含完整「高度 (cm)」，顶部不混入「指示：參考下圖…」
```

第一次用 y1=960 时顶部带进了指示行的下半截（tight 的 pad=14 把 946 也框进来），下移到 978 才干净。

**2019 Q4 最麻烦**：它的问题是「横轴标题被切」+「左下角混进选项文字」两个叠加。
`pp_recut` 的 `pad=14` 会把下方的选项行也框进来，单纯调 y2 又会切掉轴标题。
最后用 numpy 先把 `x380–650, y788–850` 涂白（抹掉选项文字残边），再在 `y314–830`、`x470–1240` 内做 tight，`pad=0` 裁出后再手工 `ImageOps.expand(border=14)` 补白边。

## 教训

1. **`pp_recut` 的 pad 是双刃剑**：它同时向外扩 14px，下边界紧邻下一行文字时会带进来。遇到这种情况改用 `pad=0` + 手工补白。
2. **轴标题在刻度数字下面**，估 y2 时要按「轴标题底部」而不是「刻度数字底部」。
3. 自动筛只能给候选，**必须拼版目检** —— 70 条命中里绝大多数是扫描噪点或照片本身的边缘。
