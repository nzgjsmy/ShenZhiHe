## V0.18.19：主题开关挡住导航 + 补齐「跟随系统」

### 用户反馈

截图显示 header 右上角的深浅色开关压在 nav 最后一项「額外資訊」上。用户建议放进设置页。

### 根因（是布局算错，不是运气不好）

```css
.hwrap{ padding:10px 60px 10px 20px; }   /* 右侧只留 60px */
.gearbtn{ position:absolute; right:12px; width:38px; }   /* 占 50px */
.themetoggle{ position:absolute; right:58px; width:52px; } /* 从 58px 往左吃掉 52px */
```

齿轮占 12+38=50px，剩 10px；开关从 58px 开始往左延伸，直接盖在 nav 上。
**两个 absolute 元素在同一角落，却只有一个被 padding 预留了空间。**

### 改法

直接删掉顶部那颗。理由：设置页本来就有「白天／黑夜／跟随系统」三颗按钮，
顶部那颗是重复入口，删掉不损失功能。

CSS 没删，改成一段注释说明为什么移除、以及怎么恢复（`.hwrap padding-right ≥ 118px`）。
删掉 50 行别人的代码风险大于收益，留注释更负责任。

### 「跟随系统」其实早就写了，但看不出来

DSH 实现了 `followSystemTheme()` 和 `matchMedia` 监听，可是：
- 三颗按钮没有任何选中态，用户不知道当前是哪个模式
- 系统切换时页面确实变了，但界面没有任何说明

补了：
- `curThemeMode()`：localStorage 有 light/dark → 手动模式；没有 → auto
- `syncThemeBtns()`：同步按钮高亮 + 一行说明
- `matchMedia` 的 handler 里也调用它，系统一变说明文字就跟着变

### 验证手段：CDP 模拟系统配色

`Emulation.setEmulatedMedia({features:[{name:'prefers-color-scheme',value:'dark'}]})`
可以真的模拟「系统切到深色」，然后检查 `data-theme` 有没有跟着变。

测了完整闭环：跟随（dark↔light 双向）→ 手动固定 → 系统再变不跟随 → 点跟随系统清空选择并立刻套用。
16 项全过。

### 遗留观察

系统**没有**偏好（`prefers-color-scheme` 两者都不匹配）时，默认取 dark。
这是 DSH 的原始选择，本次未改。如果觉得默认该是浅色，改 `followSystemTheme()` 里的兜底即可。

## V0.18.20：深色模式对比度全面修正

### 用户只看到一处，实际有 18 处

截图里是科目胶囊「化學 653 知識點」几乎看不见。但既然能坏一处，就不该只修一处。

写了审计脚本（CDP + WCAG 相对亮度公式），扫 12 个页面：首页 / 课题 / 图谱 / 测验 /
错题本 / 复习 / 真题 / 额外资讯 / 设置 / 科目总览 / 搜索 / 答题中。
对每个含文字的元素，向上找实际不透明背景（逐层 alpha 混合），算真实对比度。

结果：**18 个选择器不达标，最差 1.12:1**（AA 要求 4.5，大字号 3.0）。

### 两个根因

**根因一：亮青底配白字**

深色主题 `--accent: #2dd4bf`（亮青），但按鈕一律写 `color:#fff`。
白字在亮青上只有 1.86:1。受影响：测验本课题、开始、看笔记、齿轮、全部／只看这一类、
年份标签、nav 选中项……

解法是加一个变量，而不是逐个改颜色：

```css
--on-accent:#ffffff;                    /* 浅色 */
html[data-theme="dark"]{ --on-accent:#0d1117 }   /* 深色 */
```

**根因二：89 处为浅色写死的颜色没换成变量**

DSH 做深色模式时只转了一部分。剩下的 `#57534a`（深灰字）在深色底上只有 2.17:1，
`#f1ede4`（浅米底）在深色页上是一块亮斑。

关键判断：**这些颜色在浅色主题里的值和对应变量完全相同**，所以替换是零风险——
浅色外观一个像素都不变，只影响深色。替换了 89 处。

### 一个坑：`color:#0f766e` 会误伤 `border-color:#0f766e`

`border-color:#0f766e` 里包含子串 `color:#0f766e`，全局替换会连 border 一起改。
这次恰好是想要的（border 也该用 `--accent`），但替换顺序值得记住：
先长后短，或者用正则加边界。

### 顺带发现的既有问题（未修）

浅色模式本来就有 20 处 4.0–4.4 的边缘值（主要是 `--muted` `#7a756a` 配 `--bg` `#faf7f2`
= 4.29）。不影响阅读，但严格按 AA 是不达标的。改 `--muted` 会动到全站配色，没擅自改。

审计脚本还有 4 条 1.06 的误报——`.hero` 用 `background:linear-gradient`，
脚本只读 `background-color` 就穿透到 body 了。**教训：算对比度时渐变背景要单独处理。**

### 验证

```
深色：对比不足 18 → 0
浅色：未新增（4 条 1.06 为渐变误报）
剩余 9 个 lum=0.51 的「亮块」= 主色按钮本身，配深字后是正常设计
线上：V0.18.20 / SW_VERSION=V0.18.20
```

### 留下的约定

写进 `SHARED-MEMORY.md` **§4.11**：颜色只用变量；主色底上的字用 `--on-accent`；
新增颜色必须在 `:root` 和 `html[data-theme="dark"]` 两边都定义。

## V0.18.21：「知識圖譜」重做為「關聯地圖」

### 用户给了两个选项：删掉，或重做

先做的事是**把现状渲染出来看**，而不是马上改。

结果比预想更糟：
- 化学：12 个节点、24 条边，全部穿过中心 → 一片交叉
- 物理：20 个节点、47 条边，标签直接互相压字
- 物理还额外做了一层「只显示核心 20 个」的过滤 —— 说明原作者也意识到画不下

### 判断：不是布局没调好，是选型错了

力导向布局适合「稀疏、想知道聚类」的图。这里的图是**稠密小世界**：
12 个课题几乎两两都有 3–6 条串连。这种图无论怎么调斥力、怎么加过滤，
结果都是一团麻。

而且用户点出了关键：**笔记页每个知识点下方已经有「这个知识点还与……相连」**，
所以图里那 100 多条知识点级连线本来就是重复信息。
图真正剩下的价值只有一个：**哪些课题该一起复习**。

那就用排行 + 星形图回答这个问题，不用全科图。

### 三个设计决定

**一、全科不画图。** 改成「关联最紧密的课题对」排行，每列 `<details>` 可展开，
展开后逐条列出「知识点A → 知识点B ＋ 为什么有关」，点名称直接跳笔记锚点。
这比图信息量更大——图只能给「有多少条」，列表能给「是什么」。

**二、单课题才画图，用星形布局。** 中心是本课题，外圈是有关联的课题。
关键性质：所有边都从中心出发，**几何上不可能交叉**。
验证方式是断言所有 `<line>` 的 `x1,y1` 完全相同（`sharedStart === 1`），
而不是靠眼睛看。

**三、课题按钮按对外关联数排序。** 34 个课题的按钮墙本来是按 id 排的，
改成按关联数排，第一行就是「最值得一起复习的」。

### 顺手修的两个既有问题

- 聚焦状态原来**不能分享、不能用浏览器上一页**（只有 `#/graph` 精确匹配，
  `#/chem/graph/2a` 会掉回首页）。补了路由。
- 数学没有 `links.json`，原来会渲染成空白图。现在显示空状态并说明。

第一版 `ly = below ? y+r+16 : y-r-10`，然后「N 條」放在 `ly+14`。

修法：上半圈标签放到圆点上方更远（`y-r-26`），「N 條」在 `ly+14` 仍在圆点外。
验证不靠截图，靠算距离：遍历所有 `text` 与所有 `circle`，
断言 `hypot(dx,dy) > r+2`，结果为空数组。

## V0.18.25：題解第十一批（bio20 光合作用，17 题）

整块空白的一章，19 题全没题解。

### 这批最实在的收获：一道真的算出来的题

`2014 Q6` 给的是钟罩＋刻度管的装置图，初始读数 **0.1 mL**、**30 分钟后 0.4 mL**。
体积增加 0.3 mL / 30 分钟 → **0.6 mL/h**。选项里 B 正好是 0.3（把 30 分钟当 1 小时），
是最容易掉的坑。

这道题的关键不在算，而在**判断方向**：读数增加＝气体体积增加＝植物**释出**气体，
光合作用释放的是**氧**，所以是「每小时释出 0.6 mL 氧」，不是「吸收 CO₂」——
因为瓶里的化学药品 X 会把 CO₂ 吸掉。

### 两题没写，理由不同

### 动手前的实测（改之前先量，别猜）

用无头 Chrome 量卡片高度：

```

```

### 真正的缺口（原以为要做很多，实测发现基础已经很全）

已有：`--ease-ios` 曲线、`--anim-k` 系数（0.5–2.0）、`data-anim` 三档降级、`.view` 进场 fade、`.pip` 画中画已是 iOS 式（visibility+opacity+transform）。

**真正的缺口只有一处但影响最大**：`.ppans`（答案與題解）用 `hidden` 属性切换 → 瞬间显示 → **整页高度「啪」地突变，视线丢失**。这是 374 道题最高频的交互。

### 改法

1. **`.ppans` 高度过渡**：`display:grid` + `grid-template-rows:0fr↔1fr`。
   - 纯 CSS，不需要 JS 量高度，不会因为内容异步加载算错。
   - 结构和动效一起过渡：`grid-template-rows / margin-top / padding-top / border-color / opacity`，收起时 `visibility` 延迟到动画结束才 hidden（读屏不会念出未展开的答案）。
   - HTML 加一层 `.ppans-in{overflow:hidden;min-height:0}`——**这一层是必须的**，否则 0fr 时内容会溢出显示。
2. **`ppToggle` / `ppPick`**：`hasAttribute('hidden')` → `classList.contains('open')`。
3. **按压手感**：按下 `.09s` 立即响应，松手走各元素原本的 `.3s ease-ios` 回弹。只覆盖 `transition-duration`，不动各元素自己的 transition 简写（避免破坏 hover）。
4. **测验题解 `.expl.show`**：`.18s fade` → `.32s ease-ios`。
5. **关联地图 `<details>`**：原生 details 高度无法用 CSS 过渡（`::details-content` 兼容性不够），退而求其次让内容淡入下滑，至少不硬跳。
6. **`.pip` 与进度条**缓动统一 `--ease-ios`。
7. **降级**：`data-anim="simple"` 关掉 lklist 的装饰动画；`prefers-reduced-motion` 下展开过渡直接切（`.ppans,.ppans.open{transition:none}`）。

### 踩的坑

**坑：测试测出「收起后高度不回去」和「分隔线是 transparent」，两次都是测试写错，不是代码错。**

- 第一次：虚拟时间（`--virtual-time-budget`）下等了 1.2s，实际动画没跑完 → 误判收起失败。等到 3s 就正常回到 `rows=0px / h=1 / visibility:hidden`。
- 第二次：切换主题后**页面重绘**，脚本里缓存的 DOM 节点变成孤儿 → `getComputedStyle` 返回 UA 默认值 `transparent`。重新 `querySelector` 一次就对了。

**结论：读 `getComputedStyle` 一定要确认①过渡是否已结束 ②节点是否还在 DOM 里。** 这两个坑各花了 3 轮才定位。

誤以為「2022 是英文卷」，還自己翻譯了 Q9/Q25——翻錯了：

- 官方 Q9 (2) 是「鳥類物種 A、B 和 C 具有不同的生態位」，我譯成「這三種鳥類之間存在種間競爭」
- 官方 Q25 (1) 是「生長素是由胚芽鞘的頂端生產」，我譯成「胚芽鞘可顯示不同的向光反應」

用户中途補了一句「這裡有中文版的 22 年的卷子」，回頭核對才發現整份就是中文。
**教訓：凡是從舊圖讀到的文字，一律回原卷核對，不要相信截圖的語言。**

## 补记：V0.19.1 · 2018 Q19–Q21 串題（用户提供截图后当场修完）

用户直接发了两张原卷截图（膝跳反射弧 + 三種神經元 / Q20 的选项表），我据此核对原卷，
发现的不只是「Q20 题干空」，而是**两题的内容互换了**：

- `pp_2018_q20`：题干空、选项空，但答案是 D（有一条孤零零的答案）
- `pp_2018_q21`：题干预「下列哪項組合正確指出 X 和 Y 所屬的神經元類型？」+ X/Y 对照表
  —— 这明明是 **Q20** 的内容；
  而它的选项是「小腦／脊髓／大腦皮層／延髓」—— 这对应的是**另一道题**（Q21 真題干
  「另一條神經途徑能令人感受那輕輕敲打，這途徑應連接以下哪個部位？」）。

也就是说：Q20 的题干被搬到了 Q21，Q21 的题干被挤掉了，留下 Q20 空着、Q21 张冠李戴。
这是 §4.8「吞并邻题」的一个变体——不是吞掉下一题，而是**两题错位交换**。

修法：按原卷重建三题，共用同一张图（`f19.webp` = 膝跳反射弧 + 三種神經元）：
- Q19：圖一所示反射弧的效應器是（把原来那段「【圖一：一名坐著的男子…】」长文字图注删掉，改用真图）
- Q20：以下哪個組合正確辨別 X 和 Y 所屬的神經元種類？
- Q21：另一條神經途徑能令人感受那輕輕敲打，這途徑應連接以下哪個部位？

Q20 题解讲「怎么从形态认神经元」：假单极（细胞体挂在轴突中途）= 感觉；多极且细胞体在一端 = 运动；
突起都短、细胞体居中 = 中间神经元。并补一句「膝跳反射是单突触反射，反射弧里没有中间神经元」，
这样选项 A（X=(1)）就能直接排除。

Q21 题解重写：反射走脊髓（不需意识，所以腿会自己弹起），感觉才上大脑皮层。

> **教训**：`guard_data.py` 只比对字段是否被改，查不出「内容错位」。
> 遇到「答案是 A/B/C/D 但选项全空」「题干与选项说的不是同一件事」这类，只能回原卷对。
> 用户给的两张截图 5 分钟就定位到问题，比我按 OCR 坐标一行行找快得多——
> **以后遇到这类单题问题，直接请用户截原卷图，效率最高。**
