## V0.18.19：主题开关挡住导航 + 补齐「跟随系统」

### 用户反馈

截图显示 header 右上角的深浅色开关压在 nav 最后一项「額外資訊」上。用户建议放进设置页。

### 根因（是布局算错，不是运气不好）

```css
.hwrap{ padding:10px 60px 10px 20px; }   /* 右侧只留 60px */
.gearbtn{ position:absolute; right:12px; width:38px; }   /* 占 50px */
.themetoggle{ position:absolute; right:58px; width:52px; } /* 从 58px 往左吃掉 52px */
```

齿轮占 12+38=50px，剩 10px；开关从 58px 开始往左延伸，直接盖在 nav 上。
**两个 absolute 元素在同一角落，却只有一个被 padding 预留了空间。**

### 改法

直接删掉顶部那颗。理由：设置页本来就有「白天／黑夜／跟随系统」三颗按钮，
顶部那颗是重复入口，删掉不损失功能。

CSS 没删，改成一段注释说明为什么移除、以及怎么恢复（`.hwrap padding-right ≥ 118px`）。
删掉 50 行别人的代码风险大于收益，留注释更负责任。

### 「跟随系统」其实早就写了，但看不出来

DSH 实现了 `followSystemTheme()` 和 `matchMedia` 监听，可是：
- 三颗按钮没有任何选中态，用户不知道当前是哪个模式
- 系统切换时页面确实变了，但界面没有任何说明

补了：
- `curThemeMode()`：localStorage 有 light/dark → 手动模式；没有 → auto
- `syncThemeBtns()`：同步按钮高亮 + 一行说明
- `matchMedia` 的 handler 里也调用它，系统一变说明文字就跟着变

### 验证手段：CDP 模拟系统配色

`Emulation.setEmulatedMedia({features:[{name:'prefers-color-scheme',value:'dark'}]})`
可以真的模拟「系统切到深色」，然后检查 `data-theme` 有没有跟着变。

测了完整闭环：跟随（dark↔light 双向）→ 手动固定 → 系统再变不跟随 → 点跟随系统清空选择并立刻套用。
16 项全过。

### 遗留观察

系统**没有**偏好（`prefers-color-scheme` 两者都不匹配）时，默认取 dark。
这是 DSH 的原始选择，本次未改。如果觉得默认该是浅色，改 `followSystemTheme()` 里的兜底即可。

## V0.18.20：深色模式对比度全面修正

### 用户只看到一处，实际有 18 处

截图里是科目胶囊「化學 653 知識點」几乎看不见。但既然能坏一处，就不该只修一处。

写了审计脚本（CDP + WCAG 相对亮度公式），扫 12 个页面：首页 / 课题 / 图谱 / 测验 /
错题本 / 复习 / 真题 / 额外资讯 / 设置 / 科目总览 / 搜索 / 答题中。
对每个含文字的元素，向上找实际不透明背景（逐层 alpha 混合），算真实对比度。

结果：**18 个选择器不达标，最差 1.12:1**（AA 要求 4.5，大字号 3.0）。

### 两个根因

**根因一：亮青底配白字**

深色主题 `--accent: #2dd4bf`（亮青），但按鈕一律写 `color:#fff`。
白字在亮青上只有 1.86:1。受影响：测验本课题、开始、看笔记、齿轮、全部／只看这一类、
年份标签、nav 选中项……

解法是加一个变量，而不是逐个改颜色：

```css
--on-accent:#ffffff;                    /* 浅色 */
html[data-theme="dark"]{ --on-accent:#0d1117 }   /* 深色 */
```

**根因二：89 处为浅色写死的颜色没换成变量**

DSH 做深色模式时只转了一部分。剩下的 `#57534a`（深灰字）在深色底上只有 2.17:1，
`#f1ede4`（浅米底）在深色页上是一块亮斑。

关键判断：**这些颜色在浅色主题里的值和对应变量完全相同**，所以替换是零风险——
浅色外观一个像素都不变，只影响深色。替换了 89 处。

### 一个坑：`color:#0f766e` 会误伤 `border-color:#0f766e`

`border-color:#0f766e` 里包含子串 `color:#0f766e`，全局替换会连 border 一起改。
这次恰好是想要的（border 也该用 `--accent`），但替换顺序值得记住：
先长后短，或者用正则加边界。

### 顺带发现的既有问题（未修）

浅色模式本来就有 20 处 4.0–4.4 的边缘值（主要是 `--muted` `#7a756a` 配 `--bg` `#faf7f2`
= 4.29）。不影响阅读，但严格按 AA 是不达标的。改 `--muted` 会动到全站配色，没擅自改。

审计脚本还有 4 条 1.06 的误报——`.hero` 用 `background:linear-gradient`，
脚本只读 `background-color` 就穿透到 body 了。**教训：算对比度时渐变背景要单独处理。**

### 验证

```
深色：对比不足 18 → 0
浅色：未新增（4 条 1.06 为渐变误报）
剩余 9 个 lum=0.51 的「亮块」= 主色按钮本身，配深字后是正常设计
线上：V0.18.20 / SW_VERSION=V0.18.20
```

### 留下的约定

写进 `SHARED-MEMORY.md` **§4.11**：颜色只用变量；主色底上的字用 `--on-accent`；
新增颜色必须在 `:root` 和 `html[data-theme="dark"]` 两边都定义。

## V0.18.21：「知識圖譜」重做為「關聯地圖」

### 用户给了两个选项：删掉，或重做

先做的事是**把现状渲染出来看**，而不是马上改。

结果比预想更糟：
- 化学：12 个节点、24 条边，全部穿过中心 → 一片交叉
- 物理：20 个节点、47 条边，标签直接互相压字
- 物理还额外做了一层「只显示核心 20 个」的过滤 —— 说明原作者也意识到画不下

### 判断：不是布局没调好，是选型错了

力导向布局适合「稀疏、想知道聚类」的图。这里的图是**稠密小世界**：
12 个课题几乎两两都有 3–6 条串连。这种图无论怎么调斥力、怎么加过滤，
结果都是一团麻。

而且用户点出了关键：**笔记页每个知识点下方已经有「这个知识点还与……相连」**，
所以图里那 100 多条知识点级连线本来就是重复信息。
图真正剩下的价值只有一个：**哪些课题该一起复习**。

那就用排行 + 星形图回答这个问题，不用全科图。

### 三个设计决定

**一、全科不画图。** 改成「关联最紧密的课题对」排行，每列 `<details>` 可展开，
展开后逐条列出「知识点A → 知识点B ＋ 为什么有关」，点名称直接跳笔记锚点。
这比图信息量更大——图只能给「有多少条」，列表能给「是什么」。

**二、单课题才画图，用星形布局。** 中心是本课题，外圈是有关联的课题。
关键性质：所有边都从中心出发，**几何上不可能交叉**。
验证方式是断言所有 `<line>` 的 `x1,y1` 完全相同（`sharedStart === 1`），
而不是靠眼睛看。

**三、课题按钮按对外关联数排序。** 34 个课题的按钮墙本来是按 id 排的，
改成按关联数排，第一行就是「最值得一起复习的」。

### 顺手修的两个既有问题

- 聚焦状态原来**不能分享、不能用浏览器上一页**（只有 `#/graph` 精确匹配，
  `#/chem/graph/2a` 会掉回首页）。补了路由。
- 数学没有 `links.json`，原来会渲染成空白图。现在显示空状态并说明。

### 踩坑：星形图上半圈的标签落进了圆点里

第一版 `ly = below ? y+r+16 : y-r-10`，然后「N 條」放在 `ly+14`。
上半圈（`y-r-10+14 = y-r+4`）正好在圆点内部 → 被圆点盖住。

修法：上半圈标签放到圆点上方更远（`y-r-26`），「N 條」在 `ly+14` 仍在圆点外。
验证不靠截图，靠算距离：遍历所有 `text` 与所有 `circle`，
断言 `hypot(dx,dy) > r+2`，结果为空数组。

### 验证

```
全部模式：svg=0、24 对排行、展开 6 条串连、点知识点跳到 #/chem/t/1a@1a-s1-p4 且锚点可见
聚焦模式：7 外围节点 / 7 条边，sharedStart=1（边共用一个中心点）
点外圈：切到 #/chem/graph/3a
深色：SVG 文字 rgb(232,229,222)，面板 rgb(34,37,44)
```
