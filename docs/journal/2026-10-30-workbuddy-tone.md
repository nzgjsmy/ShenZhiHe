# 浅色主题调柔：近纯白 → 象牙纸（2026-10-30）

> 触发：用户反馈「浅色主题的时候有点太刺眼了，可能换成米白色这种柔性颜色会好很多」

## 先量化，再动手

"刺眼"是个主观感受，但可以先量出来。我写了段脚本算各底色的**相对亮度**（WCAG 定义，0=黑 1=白）：

| 变量 | 原值 | 亮度 |
|---|---|---|
| `--paper` | `#fffdf4` | **0.980** |
| `--hn-paper` | `#fffdf4` | **0.980** |
| `--paper-soft` | `#fbf9f2` | 0.947 |
| `--bg` | `#faf7f2` | 0.933 |

纸和卡片都是 0.98，几乎就是纯白。整屏铺满高亮色块，加上外面是深色桌面，明暗反差拉到最大 —— 累眼是必然的。

参考真实纸张：象牙纸约 0.88~0.91，米白约 0.92。所以目标定在 **纸 0.89 / 卡 0.94**。

## 下调方案

```
--paper       #fffdf4 (0.980) → #f6f2e4 (0.887)   紙
--hn-paper    #fffdf4 (0.980) → #fbf8ee (0.938)   卡片
--paper-soft  #fbf9f2 (0.947) → #f1ebdb (0.832)
--paper-mute  #f6f1e6 (0.882) → #ebe3d1
--paper-alt   #f2ecdf (0.842) → #e4dbc6
--line        #ece6d6 (0.793) → #dbd1bb
--bg          #faf7f2 (0.933) → #efe9da
--header-bg   rgba(250,247,242,.92) → rgba(246,242,228,.92)
--hn-note-y   #f8f0dd → #f4ead0     --hn-note-p  #e8f2ef → #e0ece8
--hn-edge     #d8cfb9 → #d3c8b0     --hn-track   #e6dfcb → #ddd3bd
```

### 关键：卡片必须比纸亮一层

如果把纸和卡片一起压到 0.89，整页会变成一块**平的暗黄**，手账感全失 —— 卡片是"贴"在纸上的，得有层次。

所以纸 0.887、卡片 0.938，差 0.05。视觉上刚好能看出卡片浮起，又不至于跳出来。

## 教训：调底色不能只调底色

纸变暗后，辅助文字 `--muted:#7a756a` 的对比度从 **4.86 掉到 4.1**。

4.1 低于 WCAG AA 的正文线（4.5）。在原来的亮白纸上勉强够用，纸一暗就不合格了 —— 这种退化肉眼很难立刻察觉，是算出来的。

所以连带把 `--muted` 调深到 `#6e6960`，才回到 4.86。

**改任何底色，都要重算落在它上面的所有前景色**，尤其是原本就"刚好过线"的那些。

## 过程中的两个小坑

**1. 注释里是繁体字，替换匹配不上。** 我先写成匹配整行（含注释），但文件里是「卡片紙（比 paper 更暖更亮）」，我写的是简体「卡片纸」。AssertionError 直接拦住了。改成只匹配 `--hn-paper:#fffdf4;` 这种「变量名+值」，不碰注释。

**2. 缩略图造成的误判。** 看整页截图时觉得顶部有一条"亮白带"，以为是 `--header-bg` 没改。实测 DOM 背景色全是新米色，放大到 3 倍才确认那只是缩略缩放导致的观感差异。顺手还是把 `--header-bg` 从 `rgba(250,247,242,.92)` 同步成了 `rgba(246,242,228,.92)` —— 虽然是次要的，但它确实是旧的亮白。
