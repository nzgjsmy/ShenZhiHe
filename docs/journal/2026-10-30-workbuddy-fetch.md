## A：把科普从 3 条扩到 20 条/科

原来的「每日小知识」各科只有 3 条，按「今天第几天 % 3」轮换——**3 天就重复一遍**，谈不上每日更新。

扩到各 20 条，合计 60，**20 天不重样**。内容全部限定在学科共识内，有争议的（如姆潘巴效应——热水结冰比冷水快，实验重复性一直有争议）**一律不收**。

写作标准：每条要有一个「啊，原来是这样」的转折，而且必须能对上 DSE 章节（`tag` 字段）。

举几个例子：

- **肌肉酸痛不是乳酸造成的**——乳酸几小时就代谢掉了，但酸痛隔天才出现。真正原因是肌纤维微损伤引起的炎症。乳酸背了很多年锅。
- **手指泡水起皱不是渗透吸水**——切断神经的手指不会起皱，这是自主神经反射，假说认为能增加湿手抓握的摩擦力。
- **飞机窗为什么是圆角**——方形转角应力集中，客舱反复增压减压就在角落起裂。1950 年代彗星客机连续解体正是这个原因。
- **核电厂为什么不会像原子弹那样爆炸**——燃料铀浓度只有 3–5%，原子弹要 90% 以上，物理上不具备条件。

### 脚本设计原则

写在 `fetch_news.py` 的文档字符串里，也是给自己看的约束：

1. **只抓有摘要的源** —— 没有摘要的卡片是残的
2. **宁缺勿滥** —— 抓不到就保持原档不变，不硬凑、不生成假内容。时事写错的代价远高于少一条
3. **一律保留原文链接** —— 用户能自己核对，不把我当唯一信息源
4. **按链接去重** —— 同一篇重复抓到不会产生重复卡片

另外过滤掉明显不是科研的内容：募资、营收、股价、财报、合作备忘录、发表会、报名、抽奖。

### workflow 设计

```
每天 UTC 22:17（港时 06:17）
  → 抓泛科学
  → git diff 检查 data/_news.json 有没有变
  → 没变：直接结束，不 build 不部署（省时间，也避免无意义提交）
  → 变了：commit 回 source → build → prep_ghpages → 部署到 main
```

#### 三个关键决定

**① schedule 先注释掉，只开 `workflow_dispatch`**

自动部署第一次必须人工盯。这个项目踩过 `cp -rn` 的 no-clobber 坑——改过的同名图片不会被覆盖，曾让 39 张图一直 404 而没人发现。CI 里如果 rsync 写错，后果一样。

验证几次确认没问题，再取消注释。

**② 部署用 `git worktree` + `rsync`，必须 `--exclude=.github`**

```bash
git worktree add --detach /tmp/deploy origin/main
rsync -a --delete --exclude='.git' --exclude='.github' gh-pages/ /tmp/deploy/
```

`--delete` 让部署目录和 `gh-pages/` 完全一致（这是对的，能清掉过期文件）。但 `.github/workflows` 是 workflow 自己的家，被删掉下次就不会跑了，所以必须排除。

没用 `peaceiris/actions-gh-pages`，因为它默认也是 rsync --delete，但要额外配 `keep_files`，不如自己写 git 命令可控。

**③ 不 bump 版本号**

一开始担心：Service Worker 用 `__SW_VERSION__` 做缓存键，不改版本号用户会不会一直看旧内容？

去读了 `site/service-worker.js` 的实际逻辑：

```js
if (req.mode === 'navigate') {
  e.respondWith(
    caches.match(req).then(function (hit) {
      var fetching = fetch(req).then(...更新缓存...);
      return hit || fetching;      // 先给缓存，同时后台更新
    })
  );
}
```

**缓存优先 + 后台更新**。所以不换缓存键也能更新——用户第一次访问拿到旧的，后台已经写好新缓存，第二次打开就是新的。

慢一次访问，但换来版本号不必天天跳。这也符合用户之前「版本号更新太快」的抱怨。

### workflow 必须在 main 上

GitHub 只从**默认分支**读 workflow 列表。这个仓库默认分支是 `main`（部署产物分支），所以 workflow 文件在 main 和 source 各存一份，用 git 对象哈希核对一致（`48efb4a`），不靠肉眼比对。
