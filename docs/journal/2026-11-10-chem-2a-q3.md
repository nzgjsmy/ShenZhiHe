## 1. 用户报的问题

一张测验卡截图：第 18 / 40 题「酸和鹼基 · 甲基橙與酚酞的變色範圍」

> 把酚酞加入 pH = 12 的溶液中，溶液會呈現下列哪種顏色？
> A. 紅色　B. 無色　C. 粉紅色　D. 黃色

界面显示 `❌ 不對喔。正確答案：無色`，但同一张卡的题解写的是：

> 酚酞的變色範圍是 pH < ~10 無色、pH > ~10 粉紅色。pH = 12 已大於 10，酚酞應呈粉紅色，故正確答案為「粉紅色」所在選項……

**题解自己算出了粉红色，答案字段却存了无色。**这是数据 bug，不是知识点争议。

## 2. 定位

题库目录结构与 bio 的 `_pastpaper.json` 完全不同，注意字段名：

- 位置：`quiz/chem/2a.json` → `questions[]` → `id = "2a-q3"`
- 字段：`q`（题干，**不是** `stem`/`question`）、`options`、`answer`、`explanation`、`point`
- `answer` 是**整数下标**（0=A），与 `data/bio/_pastpaper.json` 的字母字符串不同
- 知识点：`2a-s2-p2`「甲基橙與酚酞的變色範圍」，笔记原文为 `pH < ~10 無色 / pH > ~10 粉紅`

第一次扫描完全没命中，就是因为我按 `stem`/`question` 找题干 —— 空手而归。教训：换科目先 `json.dumps(qs[0])` 看一眼字段名。

## 3. 修法

```python
q['answer'] = 2          # 原 1（無色）→ 2（粉紅色）
```

题解同时重写。原文只给一个分界（~10），实际酚酞变色范围是 **pH 8.2–10**，写清楚更利于学生记：

> 酚酞的變色範圍是 pH 8.2～10：pH < 8.2 無色，pH > 10 呈粉紅色（強鹼中可深至紫紅）。pH = 12 遠高於 10，故酚酞呈粉紅色，正確答案為 C。B 無色是酸性或中性（pH < 8.2）時的顏色，pH = 12 已屬強鹼，不符合；A 紅色是甲基橙在酸性（pH < ~3）下的顏色；D 黃色是甲基橙在鹼性（pH > ~4）下的顏色，兩者都不是酚酞。

这样三个干扰项全部有明确归宿 —— **A/D 是另一种指示剂（甲基橙）的颜色**，这是本题最容易混的点。

## 4. 同源排查（用户上次说过「不要潦草完事」）

只修一道题不算完，得确认不是整批手写题的普遍问题。做了三轮：

### 4.1 题解显式结论 vs answer 字段

正则抓 `正確答案為「X」/ 答案為「X」/ 故選 X / 應選 X`，把 X 映射回选项下标，与 `answer` 比。

结果：**现网 0 冲突**。

但 0 命中可能是扫描器失灵，所以拿修复前的备份（`quiz/chem/2a.json.bak-phenolphthalein-*`）回测 —— 精确命中 `2a-q3 answer=無色(1) | 题解指向 粉紅色`。扫描器有效，结论可信。

### 4.2 answer 选项被题解标为错误

模式：`[ABCD] + 选项文本 + (不符合|不是|錯誤|不對|排除|…)`。

第一版做宽了（只看"否定词邻近"），命中 174 条，几乎全是噪音 —— 因为选项文本本身常含「不能」（如「能以擴散通過瓊脂塊，但不能通過雲母片」），描述的就是正确答案的性质。

收紧成「必须带字母标号 + 选项完整文本 + 紧跟否定」后，只剩 **1 条**：

- `chem/8-q1`「下列哪一項**不屬於**第四部分儀器分析方法？」答案 A 容量分析，题解写「故 A 容量分析不屬於第四部分」—— 这是**反向选择题**的正常表述，误报。

## 6. 顺带发现的隐患（本次未修）

`site/prep_ghpages.py` 的 `data_rev()` 只遍历 `data/**/*.json`：

```python
for p in sorted(glob.glob(os.path.join(root, "data", "**", "*.json"), recursive=True)):
```

**不含 `quiz/**/*.json`。** SW 缓存键是 `<版本号>-<数据指纹>`，指纹只跟 `data/` 走。所以：

> 只改测验题、但忘了 bump 版号 → 缓存键不变 → 导航请求"缓存优先"，用户第一次打开看到的是旧题，要再刷一次才新。

本次有 bump 版号（`.18`→`.19`），缓存键本身变了，无影响。但这是个静默失败类隐患，下次动 `prep_ghpages.py` 时应把 `quiz/` 一并纳入指纹计算。

## 7. 教训

1. **换科目先看字段名**。chem 用 `q`，bio `_pastpaper` 用 `q` 但 answer 是字母；phys `nuclear2` 的 answer 是整数。同一个站里三种写法。
2. **扫描器必须用「修复前的备份」回测**，否则 0 命中分不清是"真的干净"还是"规则失灵"。
3. **正则做语义检查，宽了全是噪音、窄了才可用**。174 → 1 的过程不是精度提升，是判据换了（从"邻近否定词"换成"字母标号 + 完整选项文本 + 否定"）。
4. **反向选择题（问"哪一项不属于"）会让所有"答案被否定"类检查误报**，这类题要人工看。
5. 用户报一道题，实际排查应该覆盖**同知识点 + 同文件**两个圈，再往外扩到全库一致性。这次 2a 全 40 题 + 全库两类扫描，成本不高但结论硬。
